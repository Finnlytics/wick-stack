# Changelog

All notable changes to Wick will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Initial project skeleton.
- Tooling: Credo (strict), Dialyzer, ExDoc, ExCoveralls, StreamData.
- CI: GitHub Actions running format, credo, compile-with-warnings-as-errors, tests, dialyzer.
- Stub modules for `Wick.Path`, `Wick.Value`, `Wick.Codec`, `Wick.Codec.SenmlCbor`, `Wick.Error`.
- `Wick.CoreLink` — RFC 6690 CoRE Link Format encode/decode (`application/link-format`, Content-Format 40).
- `Wick.Registration` — LwM2M 1.2 Client Registration Interface (Register / Update / Deregister). Pure data types plus `to_wire/1`; the server side lives in `Wick.Registration.Server` and uses an in-memory `Wick.Registration.Store`.
- Integration test exercising Wick + WickCoap end-to-end registration round-trip (Register → Update → Deregister) over real CoAP/UDP.
- **`Wick.Wire`** — the canonical transport-agnostic request spec, shared by every interface. Adds `:accept` and `:observe` alongside the fields `Wick.Registration.Wire` carried, and supports the RFC 8132 `:fetch` / `:ipatch` methods the Composite operations need. `to_coap_options/1` flattens a spec to `{option_number, value_bytes}` pairs and `parse/3` reverses it, so a consumer's CoAP adapter is one `map/2` per direction rather than a per-operation translation table — see [ADR 0005](docs/decisions/0005-coap-option-tuples-at-the-wick-boundary.md). `Wick.Wire.Response` is the response counterpart.
- **Device Management interface** (§6.4) — `Wick.Request.to_wire/1` and `from_wire/1` for Read, Write (replace and partial-update), Execute, Discover, Create, Delete, Write-Attributes, Read-Composite, Write-Composite, Observe, Cancel-Observe, and Observe-Composite. `from_wire/1` resolves the operations that share a CoAP method: `Accept: 40` separates Discover from Read, the presence of a Content-Format separates Write from Write-Attributes, and path depth separates Create / partial-update Write / Execute on `POST`.
- `Wick.Response.to_wire/2` and `from_wire/1`, including Location-Path and the Observe sequence number.
- **`Wick.Attributes`** — the §5.1 attributes (`pmin`, `pmax`, `epmin`, `epmax`, `gt`, `lt`, `st`, `dim`, `ssid`, `uri`, `ver`) with Uri-Query and CoRE-Link-param codecs, `merge/2` honouring the `:clear` form, and `should_notify?/3`, a pure evaluator of the §5.1.2 notification decision.
- **`Wick.Request.WriteAttributes`** — the Write-Attributes operation (§6.4.12), previously deferred.
- **Information Reporting interface** (§6.5) — `Wick.Uplink.to_wire/1` and `from_wire/1` for Notify (a `2.05 Content` carrying the Observe option) and Send (`POST /dp`). `Wick.Observation` and `Wick.Observation.Store` record the server-side Observe relations that make an inbound Notification interpretable — a Notify carries no path — with the RFC 7641 §3.4 reordering test in `accept_seq/3`.
- **Bootstrap interface** (§6.1) — `Wick.Bootstrap` with Bootstrap-Request, Write, Delete, Discover, Read, and Finish, plus `to_wire/1` / `from_wire/1`. `from_wire/1` tells Bootstrap-Request from Bootstrap-Finish by the `ep` query parameter, since both are `POST /bs`. `Wick.Bootstrap.Session` is a pure state machine that enforces the provisioning order — it will not emit Bootstrap-Finish while any step is unacknowledged.
- **`Wick.Object.Tree`** — a client's Object *values*, as pure data, complementing `Wick.Object.Registry`'s Object *definitions*. Instance lifecycle, subtree reads, per-path attributes, CoRE Links for Register and Discover, and SenML Pack conversion in both directions.
- `Wick.Codec.for_content_format/1`, `senml_codec/1`, `senml?/1`, and `content_formats/0` — resolve a Content-Format integer to the codec that implements it, which is what a request handler needs when the peer chose the format.
- `Wick.Senml.Pack.resolve/1` (applies the RFC 8428 §4.5 base-prefix rules to yield effective names and times) and `to_paths/1` (the inverse of `from_paths/1`, for reading a Composite request body).
- `Wick.Path.to_segments/1` and `from_segments/1` — conversion to and from CoAP Uri-Path form.
- End-to-end integration tests over real CoAP/UDP for Device Management (every operation against a device backed by `Wick.Object.Tree`), Information Reporting (Observe → Notify → value change → Notify → Cancel-Observe, plus Send), and Bootstrap (a full provisioning session, including Bootstrap-Finish being refused when provisioning is incomplete).

- **`Wick.Object.Registry.standard/0`** — a registry preloaded with the bundled Object catalogue, parsed at **compile time** and embedded in the BEAM. Zero file IO at runtime (verified by tracing `:file` and `:prim_file` during the call), and it works in a release that strips `priv`. `priv/ddf/` grows from three files to ten, vendored unmodified from the [OMNA LwM2M Registry](https://github.com/OpenMobileAlliance/lwm2m-registry): Security (0), Server (1), Access Control (2), Device (3), Connectivity Monitoring (4), Firmware Update (5), Location (6), Connectivity Statistics (7), OSCORE (21), Temperature (3303). Provenance and the re-sync procedure are in `priv/ddf/README.md`. This is what makes `Wick.Codec.Tlv` usable without hand-building a model first, and it supplies the Object 0 and 1 definitions the bootstrap work needs.
- **`Wick.Codec.Tlv`** — the LwM2M TLV codec, Content-Format 11542. TLV is the only content format *mandatory* in LwM2M 1.0, so this is what most of the deployed installed base speaks; without it Wick could not exchange a multi-Resource payload with a 1.0 device at all. Encodes and decodes a `Wick.Senml.Pack`, the same intermediate every other codec produces, so swapping content formats changes nothing downstream. Two options are specific to the format: `:path`, required because TLV carries no names and a payload only means anything relative to the request target, and `:model`, because a TLV value is bare bytes and only the Object definition says whether four of them are an Integer, a Float or a Time.
- **`Wick.Tlv`** — the TLV primitive underneath it: entry structure (type byte, 8/16-bit identifiers, 0/8/16/24-bit lengths, nesting) plus the per-type value encodings. Usable on its own, and it knows nothing about paths or the Object model.
- TLV fixtures under `test/fixtures/tlv/`, generated by a new `tlv` mode in `tools/leshan_oracle/`. Both implementations are handed the same declared model, which is the only way a byte comparison means anything for a format this dependent on out-of-band typing. The primitive layer is separately checked against all seven TLV examples in the LwM2M specification's §4.3, decoding and re-encoding each byte-identically.
- **`Wick.Model`** — the seam between the Object *model* and Object *values*. `resource_type/2` answers "what type is the Resource at this path declared to hold?" from a `Wick.Object.Registry`, from a plain resolver function, or from `nil` meaning no model at all. Prerequisite for the TLV and LwM2M CBOR codecs, which are not self-describing: four bytes of TLV value could be an Integer, a Float or a Time, and only the Object definition says which.
- `Wick.Object.Tree.apply_pack/3` accepts a `:model`, and stores each value under its declared type rather than the closest tag inferable from the SenML wire shape. This is what lets `/3/0/13` come back as `{:time, 1_700_000_000}` rather than `{:integer, …}`, and an Unsigned Integer stay unsigned. A value whose shape cannot satisfy the declared type — a string sent to an Integer Resource — now returns `{:error, %Wick.Error{code: :type_mismatch}}` instead of being silently stored, which is what a device needs to answer a bad Write with `4.00 Bad Request`.
- `Wick.Value.types/0` — the type vocabulary as data, and the single source of truth now shared with the model layer.

### Changed
- **Breaking:** `Wick.Object.Resource.value_type/0` is now an alias for `Wick.Value.type/0` rather than a second list of atoms, and the DDF parser emits `:core_link` where it previously emitted `:corelnk`. The two layers had drifted to different spellings of the same type; nothing crossed that boundary before `Wick.Model`, which is exactly the code that has to. Anyone matching on `:corelnk` from a parsed DDF should match `:core_link`.
- **Breaking:** LwM2M Time is an `integer()` count of seconds since the Unix epoch, not a `DateTime`. This is what every codec already implemented and what every wire format carries; only `Wick.Value`'s documentation and `@type t` said otherwise, and following them raised a `FunctionClauseError` from inside the SenML encoders. `Wick.Object.Tree.to_pack/2` now rejects a `%DateTime{}` with a message that names the mistake. Object 3 Resource 13 (Current Time) is mandatory on the Device Object, so this was reachable on the most common Read there is.
- `Wick.Object.Tree.apply_pack/3` takes either a positional base path — as before — or a keyword list of `:base` and `:model`. Existing call sites are unaffected.
- The Hex package ships `priv/ddf` rather than all of `priv`. Hex globs the filesystem and does not consult `.gitignore`, so the previous list would have swept the 4 MB Dialyzer PLT that `mix check` leaves in `priv/plts/` into the published tarball.
- **Breaking:** `Wick.Registration.Wire` is now `Wick.Wire`, and `Wick.Registration.to_wire/1` returns a `%Wick.Wire{}`. Both libraries are pre-release and unpublished on Hex, so this affects only code tracking `main`; the fix is the rename plus dropping any hand-rolled option-building in favour of `Wick.Wire.to_coap_options/1`.
- `Wick.Request.ReadComposite` and `Wick.Request.ObserveComposite` gained a `:content_format` field (defaulting to SenML CBOR, `112`) describing the *request body*, distinct from `:accept_content_format`, which asks for a format on the response. `to_wire/1` now encodes the path list itself rather than leaving it to the caller.
- Wick and WickCoap now share one repository while remaining separate packages — see [ADR 0006](docs/decisions/0006-single-repository-for-the-wick-stack.md). The `wick_coap` test dependency is a plain relative path; the GitHub fallback is gone, since it was the reason CI could never test a change spanning both libraries.

### Documentation
- The decision records are now published with the docs. They were previously repository-only, which made the *why* behind the library invisible to anyone reading it on HexDocs.
- New [ADR 0007](docs/decisions/0007-in-memory-stores-as-pure-data.md) — why `Wick.Registration.Store`, `Wick.Observation.Store`, and `Wick.Object.Tree` ship as pure data rather than processes or behaviours, and where the library/platform boundary falls. `Wick.Registration.Store` previously pointed at "ADR (TBD)" for this.
- ADR 0004 carries a dated status note: all three of its sequenced milestones are complete, and two of them landed differently from the sketch.
- Module groups on HexDocs are now pattern-based, so a new operation struct is grouped rather than falling into an ungrouped pile. Twenty-five modules were previously ungrouped.
